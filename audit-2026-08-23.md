# Shall v7 — full code audit, 2026-08-23

Point-in-time audit requested by the owner. Method: twelve independent deep-read passes covering
every directory under `src/`, every load-bearing finding re-verified line-by-line against the
tree, then a dynamic leg — the debug binary actually run on **Windows** (scratch config/data dirs,
`--dry-run` throughout) and in **WSL** (native Linux build). Reproduction recipes for every live
test are in the appendix; nothing outside `%TEMP%\opencode\audit` and `/tmp/audit-cwd` was touched.

## 1. Grades

| Dimension | Grade | One-line justification |
|---|---|---|
| **Correctness** | **B** | Defensive architecture genuinely best-in-class (compile-minted `Reaped`, WAL ordering, generation counters, refuse-don't-guess parsing). refusing flags on steps 2..n.

## 6. Missing features

- [HIGH] **No permission/ownership gate on configuration that supplies executable content.**
  `exec:` runs scripts from `config_root`; hooks/events run repo scripts; nothing validates
  mode/ownership of anything it executes from. World-writable repo + `sudo shall sync` = root
  code execution by file-drop, in a tool that otherwise hashes every approval. The repo *writes*
  modes (`hooks.rs:169`) and never *reads* them.
- [MED] **Pins end at install.** `version_pin` is consumed only in `install_group`
  (`generic.rs`); upgrade paths float past pins, reinstall rebuilds specs
  `..Default::default()` discarding versions. Planner-side filtering unverified — but the
  vocabulary lives here and stops here.
- [MED] **No decompression bound.** `max_download_bytes` sizes compressed bytes only; nothing
  bounds `tar::unpack`/zip expansion (a 40 MB zstd tens-of-GB bomb fills the disk mid-install).
  No Shall-side adversarial-archive tests either — traversal protection is delegated wholly to
  crates, untranscribed.
- [MED] **No musl/gnu axis** in artifact platform selection (`platform.rs:40-64`); on Alpine a
  `-gnu` binary wins as readily as `-musl` and fails at exec. Format layer knows "alpine";
  filename layer doesn't.
- [MED] **No batch operand caps at the generic layer** (`generic.rs:1003-1056`) — noting a
  stira between auditors: the engine pass found 6000-byte/100-name caps in `argv.rs:690-705`;
  whether every generated argv transits `push_names` is unconfirmed. If they do, this item is
  closed; if not, a 280-package adopted winget set builds one oversized CreateProcess call.
  Worth one grep and a test to settle.
- [MED] **`schedule.log` grows unbounded** (`scheduler/mod.rs:253,618`) — systemd append and
  launchd StandardOutPath point at one file with no rotation; Shall-generated, so Shall is the
  natural rotator.
- [MED] **Dry-run backstop inside `SyncEngine::sync`** (`sync/mod.rs:165-333` never reads
  `config.dry_run`) — safety rests on all N callers returning first; `profile.rs:383-409` and
  `shell/mod.rs:287-292` appear ungated (verb-flag reachability unverified). The invariant
  should live in the engine, not in everyone's memory.
- [LOW] `.wsb` generation ignores `allow_home`/custom mounts, escapes nothing (any `<,&,"`
  yields rejected XML), and has no mapped-host-folder story for the guest to find the binary.
