# How many checks each SECTION of the harness ran, per host class. A ratchet: a section's
# number may rise, and a run that falls below the recorded one fails.
#
#   <host-class>  <section name>  <n>
#   <host-class>  <section name>  <n>  soft  <excused-down-to>  <YYYY-MM-DD>  <the soft line>
#
# Fields are separated by TWO spaces, and a `#` line is a comment. A section name contains single
# spaces and sometimes a colon, an arrow and a comma, so the file is read by stripping fields off
# the front rather than by splitting a line on whitespace.
#
# WHY THIS EXISTS, and it is the mirror of a gate that already exists.
#
# `scripts/harness-mutation-test.sh` holds `CAUGHT_FLOOR`, an ABSOLUTE count of checks that
# caught a broken product, and its header says why a rate would not do: a survivor rate cannot
# tell "the checks got stronger" from "the checks were deleted". This is the same blindness in
# the other direction, and it had nothing at all in front of it. **A section that stops running
# cannot fail.** Every check it did not make is a check that did not fail, the summary prints
# `pass=… fail=…` as usual, and the run is green with a hole in it.
#
# Measured. `crash/groupkill` lost 10 of its 10 checks on the `ubuntu` image in CI 36515002965.
# The run reported one `soft` — correctly, because the SIGKILL landed outside the transaction
# window, so nothing exercised recovery, and scoring that green is the thing a check-that-
# measured-nothing must never do — and it ended `pass=391 fail=1 soft=5`, green, and eight checks
# short of the 405 the previous `main` ran on the same image with the same backend. Locating those
# eight took a scripted diff of two downloaded logs. A reader of either run could not have seen
# it.
#
# The per-section tally shipped first (5794ac3) and made the run say what it covered; this file
# is what compares it. Together they answer both halves: *did a section stop running*, and
# *which one*. The tally alone answered the second to whoever diffed two logs by hand.
#
# **KEYED BY HOST CLASS, for the reason `lifecycle-floor.txt` gives at length, and here it is not
# tidiness — it is the whole design.** The honest number is a property of the machine, not of
# the harness. `Real lifecycle, every other manager on this image` measures 125 on `tools` and 0
# on `gentoo`; `Snapshot -> mutate -> restore` measures 8 on `storage`, the only image that
# builds a volume group, and 0 on the other ten; `SIGKILL mid-transaction, then heal` measures 41
# where the fixture installs and 3 where it does not. One number over those is a number that
# reports eleven images, ten of them wrongly, and a ratchet that is wrong that often gets
# lowered, at which point it is a ceiling drawn by whoever lowered it last.
#
# The class is `<harness>-<os>[-<image>]-<ci|local>`, built exactly as `lifecycle-floor.txt`
# builds it: `SHALL_IT_IMAGE` where the Dockerfile declares one, `os-release` otherwise, and
# `docker run` passes no `CI`, so a container is always `-local`. `/etc/os-release` says `ubuntu`
# for the `tools` image too, which is why the key is the image and not the distro.
#
# A `soft` IS NOT AN EXCUSE, and this is the half that makes the file worth having. A `soft` is
# the instrument declining to measure, which is right and must stay right — so a run whose
# section is short because the harness SAID why is not a red board. But a `soft` alone would
# make every collapse excusable by the collapse itself: a section that stops running in silence
# prints no soft, and a gate that only asks "did something decline?" cannot tell that from a
# section that declined for a stated reason.
#
# So a `soft`-bound line carries BOTH halves and is honoured only when both hold:
#
#   the count — the run measured AT LEAST this many, so a collapse past it is not the same
#     event. A section that loses ten checks and one that loses nine are different findings,
#     and a line that excused both would have caught neither.
#   the text — this run printed that `soft`, in that section, this time, matched literally
#     against the lines this run actually printed. An excuse written for one image's reason
#     cannot carry another image's, and a stale excuse cannot outlive its cause silently: it
#     stops matching, and the gate goes red on the cause returning.
#
# The line does not expire, for the reason `lifecycle-floor.txt` argues at length and the owner
# ruled on: an expiry turns a single upstream rotation into a board that goes red and STAYS red,
# and a permanently red board is the failure this mechanism exists to prevent, arriving by the
# other road. The date is on the line so the debt is visible in a diff, and every run that
# honours an excuse prints the section, the count and the number it was excused to.
#
# THE NUMBERS, and which runs they came from. Every line below is the HIGHEST count a class has
# measured, over four runs of the tally across the whole matrix:
#
#   36550745873  nightly, 2026-09-29      36676516988  push, 2026-09-30
#   36606109539  push,   2026-09-29      36696775008  nightly, 2026-09-30
#
# `gentoo`, `guix`, `slackware` and `tools` appear in two of the four — they are the slow
# images, and two measurements is what there was. Their lines are the least-supported numbers
# in this file and the first to be worth re-measuring. Every other class has four.
#
# WHAT THE `soft` LINES ARE, and every one of them is the harness declining rather than Shall
# failing. Seven are the crash section, by one of its two routes: the control sync installs
# `pv dos2unix ncdu` first, and when that install did not happen the kill had nothing to
# interrupt; or the kill landed outside the transaction window and opened no new journal entry.
# The eighth is `appimage` on the `void` image, which has no FUSE in a plain container. Each is
# recorded with the lowest count that cause has actually produced and with the words of the line
# that produced it, so a run that falls further than the cause explains still fails.
#
# **Three of the seven carry a bound their own class has not printed yet** — `arch`, `opensuse`
# and `ubuntu` have run that section 41 times flat, with no soft, in the four runs above. The
# bound is 22 because that is what the same cause produced on `alpine`, `fedora` and `storage`,
# and the second condition still applies in full: **the excuse is honoured only when the run
# prints that line**, so a bound written in advance of its first occurrence can hide nothing and
# only saves a leg the false red of a coin-flip kill landing outside a transaction window. The
# `tools` bound is 3 rather than 22 because its own low was 3, from the other route: its fixture
# did not install at all.
#
# ONE SECTION DELIBERATELY HAS NO BLOCK, and it is this gate's own. The harness's section 18 is
# "Did every section run, against the record", and it scores exactly one check — so its count is
# 1 or 0 by construction, and a floor over that would compare 1 against 1 forever and catch
# nothing. Every run prints the line to add for it and counts it as neither, which is the correct
# answer for a quantity with no variance. A block appears here when a section's checks can differ
# from one run to the next; until then, this file saying nothing about it is the honest record.
#
# **WHAT THIS DOES NOT COVER, said here rather than discovered.** These are the container
# matrix's numbers. `scripts/integration-windows.sh` and the macOS native sweep have no section
# tally, so this file holds nothing for them and the gate is in force on neither — the same
# gap Q12's rule 6 ("both harnesses carry it") was written to close for the lifecycle floor,
# and the same half-open state. Porting the tally is the prerequisite, and it is not this
# change. A class with no block here is neither passed nor failed: the run prints the lines to
# add and counts the section as neither, because a record that is not there compares nothing.
#
# TO RAISE ONE: run the matrix, read the number the run prints, edit the line, commit it. Every
# ratchet-up `sed` the run prints is the edit. **Never lower a line to get green** — that is
# the one edit this file exists to make visible in a diff, and it is the edit that turns a
# ratchet into a comment.
